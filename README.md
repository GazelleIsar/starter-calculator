# 起手式｜YGOPro 卡組啟動機率計算器

這是一個完全在本機執行的 YGOPro `.ydk` 主牌組檢視器與蒙地卡羅啟動率計算器。程式不會修改 YGOPro、牌組或卡圖；唯一會建立的執行期檔案是本資料夾中的 `config.json` 路徑設定。

## 開始使用

1. 雙擊 `啟動卡組計算器.bat`。
2. 第一次開啟時，選擇任意名稱的 YGOPro 主目錄（例如 `ygopro`、`ygopro2`）。
3. 程式會自動尋找該目錄下的 `pics`；若找不到，按「另選」指定卡圖資料夾。
4. 載入 `.ydk` 檔。程式只讀取 `#main` 以下、`#extra` 以上的卡片密碼。
5. 依需求添加「手牌啟動」或「墓地／除外啟動」，將左側卡片或自訂卡片拖至條件欄。也可先點選正式卡，再點目標欄位。
6. 設定起手張數與模擬次數，按「計算啟動率」。
7. 如需估算完整賽局勝率，可在「賽局模擬」設定先後手條件並選擇直接計算或從目標反推。

右側另有一個判定改寫欄及四種卡位分類：

- **改變卡片判定**：只接受已設定完成的「特殊判定－抽牌／堆墓或除外」。特殊判定只有放入此欄後才會影響模擬。

- **浮動卡位**：同密碼的左側卡圖會降低明度；仍可同時加入任何啟動組合。
- **先手阻抗**：用來標記先攻時的阻抗卡，可與浮動卡位、後手對策和啟動組合重疊。
- **後手對策**：用來標記後攻時的對策卡，可與浮動卡位、先手阻抗和啟動組合重疊。
- **卡組廢件**：用來標記不希望在起手抽到的卡，可與其他分類及啟動組合重疊。

四種卡位分類僅用於整理與報告，不會改變蒙地卡羅啟動率；「改變卡片判定」則會改變同一次模擬的手牌或墓地／除外結果。

瀏覽器頁面開啟後，請保留命令視窗。關閉命令視窗即會停止本機伺服器。

## 啟動問題

- 啟動器會自動尋找 `py` 或 `python`，並確認它確實是 Python 3。
- 若啟動失敗，命令視窗現在不會立即關閉，而會顯示錯誤與退出代碼。請保留該訊息以便診斷。
- 如果伺服器已啟動但瀏覽器沒有自動開啟，請將命令視窗顯示的 `http://127.0.0.1:連接埠/` 貼到瀏覽器。

## 判定規則

- 「手牌啟動」中的手牌需求必須全部成立；重複放入同一密碼代表需要抽到相同張數。
- 同一組合中的「不可上手」卡只要任一張出現，該組合便不成立；此欄可留空。
- 「墓地／除外啟動」只判定墓地／除外結果需求；需求全部成立時該組即為 `True`，不再另設手卡需求。
- 手牌啟動、墓地／除外啟動及多個啟動組合之間採 `OR`：任一組成立，該次試抽即為成功。
- 抽牌採無放回抽樣。顯示結果為 `成功次數 / 總模擬次數`，並附上近似 95% 信賴區間。
- 同一次模擬也會以相同的起手張數與抽牌結果，報告「先手抽到阻抗的期望張數」及「後手抽到對策的期望張數」。
- 期望張數會尊重分類中的實際張數；例如牌組有三張同密碼卡、先手阻抗只放入兩張，模擬只把其中兩張標記為先手阻抗。
- 兩項期望報告另顯示該次起手牌「至少抽到一張」的模擬機率。
- 卡組廢件報告使用同一次模擬的手牌，顯示平均每幾局會至少抽到一張廢件，並附上該事件的模擬機率。
- 組合會依牌組內容保存在瀏覽器本機儲存空間；再次載入相同牌組時會自動還原。
- 浮動卡位、先手阻抗、後手對策與卡組廢件亦會依牌組內容分別保存。

## 自訂卡片與特殊判定

- **OR**：成員中的任一條件於手牌成立即為 `True`。
- **AND**：成員中的所有條件都必須於手牌成立，且不同條件需要對應不同的實體卡片。
- **特殊判定－抽牌**：先指定一張「改變處理方式的卡」及觸發位置；原卡在手牌或墓地／除外區域公開時立即判定，成立後從目前牌頂額外抽指定張數並加入手牌，再重新判定所有效果與啟動組合。
- **特殊判定－堆墓或除外**：觸發方式相同；成立後從目前牌頂將指定張數送入獨立的墓地／除外區域，並立即判定新公開卡片的特殊效果。
- 特殊判定的原卡只能是牌組內的單一正式卡；附加條件可以留空。若有附加條件，條件可包含正式卡或先前建立的 OR／AND 自訂卡，並與原卡在同一觸發位置判定。多個條件採 `AND`；需要任一成立時可先建立 OR 自訂卡。
- 特殊判定不能放入啟動組合、卡位分類或其他自訂卡，只能放入右側「改變卡片判定」欄；建立完成但尚未放入該欄時不會生效。
- **觸發次數**：限制同一項特殊判定在一次模擬中最多處理幾次，預設為 1。每次處理仍須對應一張已在觸發位置公開的原卡副本；兩張同名卡搭配 1 次限制只會處理一次，單一副本也不會因上限設為 2 而自行重複處理。
- 抽到手牌或送入墓地／除外的新卡都會立即公開並繼續觸發其他特殊判定。多項同時成立時依「改變卡片判定」欄中的順序處理。
- 作用域可設為僅先手、僅後手或先後手皆可。「計算啟動率」視為先手；賽局模擬會分別依先手與後手套用。
- 額外抽到手牌的卡會納入啟動組合、阻抗、對策及廢件報告；堆墓／除外的卡只進入獨立區域，不算在手牌內。

## 賽局模擬

- 「成立啟動組合」是同一次模擬中同時成立的手牌啟動與墓地／除外啟動總數。
- 先手使用目前設定的起手張數；後手使用同一副洗牌結果並多抽一張。每次試抽同時記錄 `TT`、`TF`、`FT`、`FF`。
- 直接勝率計算會依目前的啟動組合、先手阻抗與後手對策設定，分別報告先手勝率、後手勝率及兩者平均的綜合勝率。
- 從目標反推會逐一比較同密碼卡的「浮動張數」與「牌組總張數」；只有全部副本都在浮動卡位時，才會從既有條件排除該卡。若只把三張中的一或兩張列為浮動，固定核心仍有副本，相關啟動組合、先手阻抗與後手對策會繼續保留。自訂 OR 只排除已完全浮動的成員；只要仍有其他成員可用，該組合便不會被刪除。必要條件已無可用成員時會屏蔽整個組合，不會留下被簡化的組合。
- 可用配置共有六項：「啟動」、「先手阻抗」、「後手對策」、「啟動＋先手阻抗」、「啟動＋後手對策」、「後手對策＋先手阻抗」。使用者需選擇 1～3 項；未勾選的配置完全不會納入最佳化。
- 反推結果會列出最佳分配及其先手、後手與綜合勝率。若模擬次數超過 100,000，最佳化階段會使用 100,000 次共同試抽以控制等待時間，並在結果中標示。

## 開發與測試

```powershell
python server.py --no-browser
node --test tests/core.test.mjs
```

伺服器僅監聽 `127.0.0.1`。前端只能透過受限 API 讀取設定卡圖目錄中、以純數字密碼命名的圖片。
